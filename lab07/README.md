# Лабораторная работа № 7: результат Activity и восстановление данных

Приложение `ru.example.lab07` на Kotlin и Jetpack Compose выбирает текстовый документ через системный Storage Access Framework, показывает начало файла, экспортирует заметку и открывает HTTPS-ссылки во внешнем браузере. Выбор и создание документов используют Activity Result API.

## Сборка и автоматические проверки

Откройте эту папку как проект Android Studio, дождитесь Gradle Sync и выберите устройство с Android API 24 или новее. Из PowerShell в корне проекта:

```powershell
.\gradlew.bat :app:assembleDebug :app:lintDebug
```

APK появится в `app/build/outputs/apk/debug/app-debug.apk`. В выполненной проверке сборка и lint завершились `BUILD SUCCESSFUL`; ошибки lint исправлены.

Для локальных unit-тестов в текущем Windows-каталоге с кириллицей использована команда:

```powershell
.\gradlew.bat :app:testDebugUnitTest '-Dorg.gradle.jvmargs=-Xmx2048m -Dfile.encoding=windows-1251' --no-configuration-cache
```

Этот параметр обходит проблему кодировки пути при запуске тестового JVM-процесса на данном Windows-компьютере; кодировка документов в приложении остаётся UTF-8. В каталоге с ASCII-путём обычно достаточно `gradlew.bat :app:testDebugUnitTest`, а в Linux/macOS — `./gradlew :app:testDebugUnitTest`.

На подключённом тестовом устройстве или эмуляторе:

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest
```

Проверены 10 unit-тестов и 12 инструментальных тестов: все прошли. Инструментальные проверки охватывают реальные потоки `ContentResolver` для тестовых файлов, состояния интерфейса и пересоздание Activity. Файловые тесты используют `cacheDir` и `Uri.fromFile`; работу системного выбора SAF следует дополнительно проверить вручную.

Тест `initialScreenShowsDefaultAddressAndNoSelectedFile` требует начального состояния приложения без сохранённого URI. Для воспроизведения всей серии используйте свежий эмулятор / свежую установку либо чистые данные отдельной тестовой установки. Запускайте эту серию до ручного выбора документов на том же экземпляре приложения; после ручной проверки используйте отдельный свежий эмулятор. Не сбрасывайте данные приложения на чужом телефоне ради теста. Сам набор тестов пользовательские настройки не очищает.

Отчёты после запуска находятся в `app/build/reports/tests/testDebugUnitTest/`, `app/build/reports/androidTests/connected/` и `app/build/reports/lint-results-debug.html`.

## Что и как сохраняется

Небольшая заметка (до 4000 UTF-16 единиц), HTTPS-адрес и URI текущего состояния используют `rememberSaveable`. Они восстанавливаются при повороте или пересоздании Activity. `rememberSaveable` не служит постоянным хранилищем черновика: после принудительной остановки и нового холодного запуска неэкспортированная заметка может сброситься. Для постоянного сохранения нажмите «Экспортировать заметку».

URI последнего открытого и последнего экспортированного документа сохраняются в `SharedPreferences`, только если получено постоянное разрешение на чтение через `takePersistableUriPermission`. Сам текст файлов в настройках не хранится. Операционная система хранит разрешение отдельно от URI. При восстановлении приложение перечитывает документ; удаление файла или отзыв доступа обрабатываются сообщением. Ненужные старые разрешения освобождаются, а доступ к URI, используемому другим сохранённым полем, сохраняется.

Предпросмотр читает максимум 500 UTF-16 единиц Kotlin `Char` в UTF-8 через `Dispatchers.IO`. Он не загружает весь большой файл в состояние Compose или `Bundle`. Чтение идёт циклом, поскольку один вызов `read` не обязан заполнить буфер. Пустой файл является допустимым результатом.

Экспорт через `CreateDocument("text/plain")` записывает весь текст заметки в UTF-8 с режимом `wt`, закрывает поток и затем сообщает об успехе. Для открытия экспорта используется внешний `ACTION_VIEW` с типом `text/plain` и временным READ-разрешением. На устройстве может отсутствовать подходящий текстовый просмотрщик: приложение показывает сообщение; наличие сохранённого файла от этого не зависит.

HTTPS-ссылка проверяется до запуска внешнего браузера. Отсутствие подходящего браузера также обрабатывается. Главный экран прокручивается целиком, чтобы элементы оставались доступны при повороте, показе клавиатуры и размере шрифта 150%.

## Тестовые документы

- `samples/lab07_empty.txt` — файл длиной 0 байт.
- `samples/lab07_utf8.txt` — короткий UTF-8-текст с кириллицей и переводами строк.
- `tools/New-LabSamples.ps1` — создаёт большой файл `samples/lab07_long_20mb.txt` только при явном запуске. Размер — ровно 20 МиБ (20 971 520 байт), кодировка UTF-8 без BOM.

```powershell
.\tools\New-LabSamples.ps1
```

Повторная генерация существующего большого файла требует явного параметра `-Force`. Файл исключён из Git и не создаётся при сборке. Перед ручной проверкой скопируйте нужные образцы на тестовое устройство, например в `Download`, чтобы их можно было выбрать в системном диалоге.

## Три обязательных эксперимента

1. **Отмена выбора.** Нажмите «Выбрать файл» и вернитесь из системного диалога кнопкой «Назад», не выбирая документ. Ожидается сообщение об отмене, отсутствие падения и сохранение прежнего предпросмотра, если он был. Аналогично отмените «Экспортировать заметку»: файл не считается успешно экспортированным.
2. **Пустой документ.** Выберите `lab07_empty.txt`. Ожидается сообщение о пустом файле без исключения. Затем выберите `lab07_utf8.txt` и проверьте кириллицу. Для дополнительной проверки выберите сгенерированный файл 20 МиБ: интерфейс должен показать только первые 500 UTF-16 единиц.
3. **Некорректный HTTPS-адрес.** Введите `http://example.org`, `https://` либо строку с пробелом внутри адреса и нажмите «Открыть сайт». Ожидается подсказка «Введите корректный HTTPS-адрес»; переход во внешний браузер не выполняется. Затем проверьте `https://developer.android.com`.

## Восстановление, экспорт и доступность

1. Выберите UTF-8-документ, введите заметку и измените корректный HTTPS-адрес. Поверните устройство. Заметка и адрес должны сохраниться, предпросмотр — восстановиться чтением по URI.
2. Экспортируйте заметку в `note.txt` через системный диалог. Нажмите «Открыть сохранённый файл». При наличии текстового просмотрщика он должен получить документ с точным текстом и переводами строк. При отсутствии просмотрщика ожидается понятное сообщение.
3. Закройте и заново запустите приложение. Проверьте восстановление URI и доступность сохранённого экспорта. Для проверки холодного запуска на собственном тестовом устройстве можно принудительно остановить приложение через настройки Android и открыть его снова: сохранённые URI и экспортированный файл должны остаться, а неэкспортированный черновик при таком запуске не обязан восстанавливаться.
4. Удалите только созданный для эксперимента документ либо отзовите доступ средствами провайдера, затем повторите открытие. Ожидается сообщение об ошибке вместо падения.
5. Установите размер шрифта Android 150%, проверьте портретную и альбомную ориентации. Прокрутите до всех кнопок, введите текст с открытой клавиатурой и убедитесь, что элементы остаются доступны. После эксперимента верните выбранный ранее размер шрифта.
